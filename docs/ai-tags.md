# AI-подсказки тегов

Текущий провайдер: **Polza, Gemini 2.5 Flash Lite** (`google/gemini-2.5-flash-lite`).

Поток: Firebase Auth → Cloudflare Worker → проверка прав через Firestore → Polza → JSON с существующими тегами. Вызовы модели платные; Cloudflare Workers и Firebase остаются на бесплатных тарифах.

## Доступ и расходы

- Отдельный ключ Polza **«Папина полка — теги»** ограничен **общим разовым расходом 50 ₽**, не суточным лимитом. Разрешена только Gemini 2.5 Flash Lite. Ограничения установлены на стороне Polza.
- Логирование содержимого запросов и неофициальные провайдеры отключены.
- Значение ключа хранится только в Cloudflare Secret `POLZA_API_KEY`, в репозиторий и веб-сборку не входит.
- Worker принимает запросы только с двух Origins Firebase и дополнительно проверяет Firebase ID token через защищённый запрос к Firestore. Детские аккаунты вызывать модель не могут.
- В модель отправляются название видео и список существующих тем. Firebase token передаётся только в Google; заметки и библиотека видео в модель не отправляются.
- Дополнительный лимит Worker: 40 новых запросов за сутки UTC и 10 за минуту для провайдера. Счётчик SQLite Durable Object сохраняется при перезапусках.
- Кэш на сутки привязан к родителю, названию, темам, модели и маршруту. Он содержит идентификаторы тегов; ключ — SHA-256. Повторный запрос не вызывает модель.

## Поведение формы

Название может загрузиться из YouTube или быть введено вручную. Через паузу после изменения названия запрашиваются AI-подсказки. Ответы для старого названия и закрытой формы игнорируются.

После ручного изменения галочек AI не меняет выбор. Кнопка «Применить подсказки» явно применяет текущую рекомендацию. Новые темы автоматически не создаются. При сбое API, исчерпании лимита или некорректном ответе используется подбор по ключевым словам.

## Развёртывание и обслуживание

- Worker: `https://papina-polka-tags.alx-voropaev.workers.dev`.
- Исходники и настройки: `cloudflare/worker.mjs`, `cloudflare/wrangler.jsonc`.
- В основной конфигурации сохранён `LLM_PROVIDER=polza`; режим `openrouter` существует отдельно и не включается автоматически.
- Публичный адрес API: `public/ai-config.json`. Ключей в нём нет.
- `npm run check:worker` проверяет сборку без публикации; `npm run deploy:worker` публикует Worker. Существующие секреты наследуются при публикации.
- Для ротации ключа используйте интерактивный `npx wrangler secret put POLZA_API_KEY --config cloudflare/wrangler.jsonc`. Не помещайте ключ в аргументы shell-команды, файлы в `public/` или чат.
- Если меняется адрес Worker: `node tools/configure-ai-endpoint.mjs https://NAME.SUBDOMAIN.workers.dev/suggest`, затем пересоберите APK. Для прежнего клиента выполните `npm run build:firebase` и опубликуйте Hosting. Скрипт обновляет адрес в Android и в веб-конфигурации, включая CSP.
- Изменение провайдера, модели или лимита расходов требует отдельного решения пользователя.

Модульные и API-тесты (`npm test`) проверяют права доступа, ограничения источников запроса, валидацию ответа модели, кэш, квоту, защиту ручных изменений и явный выбор платного провайдера. Браузерный сценарий Firebase Emulator проверяет заполнение формы и сохранение тегов с имитацией LLM. Живой тест — `.tooling/verify-live-ai.mjs`.

### Почему заменён OpenRouter

Один и тот же ключ OpenRouter успешно получил бесплатный ответ напрямую с компьютера, но запросы из Cloudflare к генерации и `/api/v1/key` возвращали `403 Access denied by security policy`. Проверка размещения US East также вернула 403; фактическое исполнение `remote-IAD` подтверждено, после проверки исходное размещение восстановлено. Точная причина ограничения на этом сетевом пути неизвестна. Ключ не был испорчен; проблема обойдена заменой API на Polza по запросу пользователя. AI Gateway не создавался, поскольку рабочий вариант через Polza уже подтверждён.
