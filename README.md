# Видео полка

Семейная подборка видео YouTube. Родитель добавляет ссылки, а ребёнок смотрит подборку на другом устройстве. Android-приложение использует нативные экраны для входа, каталога и настроек. Firebase Authentication управляет входом, а Cloud Firestore хранит семейную полку.

[Проект в Firebase Console](https://console.firebase.google.com/project/papina-polka-bec464/overview)

## Использование на двух телефонах

1. Скачайте APK из [последнего релиза GitHub](https://github.com/AlxVoropaev/papapp/releases/latest) и установите его на устройства с Android 8.0 или новее. Для воспроизведения нужен актуальный Android System WebView и доступ к YouTube.
2. На своём телефоне выберите **Войти как родитель** и введите почту и пароль. Для новой полки выберите **Создать полку**. Для первоначальной настройки понадобится одноразовый ключ создания.
3. Откройте **Настройки → Подключить устройство**. Введите шестизначный код на втором устройстве, например `123 456`. Код действует 10 минут и используется один раз. Новый код отменяет предыдущий.
4. Нажмите **Добавить видео** или отправьте ссылку из YouTube через **Поделиться → Видео полка**. Название загрузится автоматически. При желании исправьте его, отметьте темы или добавьте заметку. Открытая детская полка проверяет изменения каждые 10 секунд и при возвращении в приложение.
5. В настройках родитель может отключить доступ детских устройств и выдать новый код.

Видео воспроизводится в карточке ленты. Официальный плеер YouTube занимает место обложки и поддерживает полноэкранный режим. WebView используется только в области плеера. Автор видео должен разрешать встраивание. Правила YouTube управляют рекламой и рекомендациями в плеере.

При первом переходе с APK 0.5.0 на нативную версию родитель повторно входит по прежней почте и паролю, а детское устройство подключается по новому коду. Видео, темы и заметки остаются в той же полке Firestore. Следующие обновления нативного APK сохраняют нативную сессию.

### Добавление через Android «Поделиться»

В YouTube откройте видео или Shorts → **Поделиться** → **Ещё** → **Видео полка**. Приложение откроет форму с заполненной ссылкой. Дождитесь автоматического названия или введите его вручную, отметьте нужные темы и нажмите **Добавить на полку**. Ссылка, полученная до входа, откроется после входа родителя.

Поддерживаются ссылки на видео YouTube, Shorts и прямые трансляции, переданные как текст или HTML. Можно делиться ссылкой из браузера. Добавление доступно в родительском режиме.

## Развёртывание в Firebase

В семейной сборке настроен действующий Firebase-проект. Приложение обращается непосредственно к Firebase Authentication и Firestore. Для другого проекта сборка принимает адрес Firebase Hosting, откуда считывает только служебную конфигурацию проекта.

- Для нового проекта создайте Cloud Firestore Standard `(default)` и включите вход по почте и анонимную аутентификацию.
- Опубликуйте правила из `firestore.rules`. Для первоначальной настройки создайте запись `setupSecrets/<sha256-ключа-в-hex>` с полем `enabled: true`. На первом устройстве введите исходный ключ.
- Соберите APK. Для семейного проекта достаточно `./tools/build-local-apk.sh --cloud`. Чтобы указать другой проект, передайте его адрес `https://PROJECT_ID.web.app` вторым аргументом. Для сборки нужны JDK 17, Android SDK Platform 35 и Build Tools 35.0.0. Задайте `JAVA_HOME` и `ANDROID_SDK_ROOT`. Android Studio может открыть проект из каталога `android/`.

## Совместимость с прежним APK

Опубликованный сайт и его механизм обновления нужны установленным ранее версиям APK, пока они переходят на нативную сборку. [Прежняя версия полки](https://papina-polka-bec464.web.app)

После `npm run build:firebase` и публикации Hosting открытые экземпляры прежнего клиента проверяют `/version.json` при запуске, возвращении на экран, восстановлении сети и раз в три минуты на активном экране. Новый APK для изменения веб-интерфейса не нужен.

Обновление перезагружает страницу только на активном экране, когда закрыты все диалоги, включая плеер и формы, завершены запросы и нет ожидающей обработки ссылки из «Поделиться». Пауза видео не разрешает обновление: нужно закончить просмотр или закрыть плеер. Перед перезагрузкой есть пауза 1,5 секунды и повторная проверка версии, доступности сервера и состояния интерфейса. При ошибке сети или чтения версии текущая страница продолжает работать. Обновление не очищает данные входа и подключения устройства.

Сборка вычисляет идентификатор из содержимого интерфейса, встраивает его в HTML и публикует вместе с `version.json`. JavaScript и CSS лежат в `releases/<версия>/`; предыдущие каталоги сохраняются при повторной сборке, чтобы уже загружающиеся страницы могли получить свои файлы. При переносе сборки на другую машину для такого сохранения нужно перенести и предыдущие каталоги `releases/`. Локальный SQLite-прототип без встроенного номера версии не проверяет обновления. В родительских настройках облачной сборки отображаются имя и номер релиза из `android/version.properties`.

Однажды уже открытая страница старой версии без этого механизма должна быть перезагружена вручную или заново открыта после завершения процесса приложения. Последующие веб-обновления она получает автоматически.

## Локальная проверка

- `bash tools/test-android-share.sh` проверяет извлечение ссылок из сообщений Android (нужен `JAVA_HOME` с JDK 17).
- `bash tools/test-android-updates.sh` проверяет ограничения версии, URL, размера, хеша и путей APK.
- `PLAYWRIGHT_MODULE=/путь/к/playwright/index.mjs node tools/verify-apk-safety.mjs` проверяет, что прежний веб-клиент откладывает переход на нативный APK при открытой форме, сохранении и просмотре видео.
- `ANDROID_TEST_SERIAL=emulator-5556 node tools/verify-apk-updates.mjs` проверяет скачивание, неправильные хеши и подписи, ожидание безопасного момента, системное подтверждение и автоматическую установку. Нужен отдельный запущенный эмулятор Android 14; физические устройства скрипт отклоняет. Скрипт временно устанавливает тестовые сборки `polka.mobile` и после проверки восстанавливает начальную тестовую версию, не удаляя приложение.
- `firebase emulators:exec --project demo-papina-polka --only auth,firestore 'npm run test:firestore'` проверяет правила Firestore. Для Firebase Emulator Suite нужен JDK 21.
- `npm run build:firebase -- --emulator` собирает отдельную тестовую веб-версию в `dist/firebase-emulator`, использующую Auth и Firestore на localhost. Публикуемая версия собирается отдельно в `dist/firebase`.
- `npm start` запускает локальный сервер SQLite на `http://127.0.0.1:3080`. Для проверки нативного приложения с этим сервером соберите `./tools/build-local-apk.sh --local`, настройте `adb reverse tcp:3080 tcp:3080` на тестовом эмуляторе и введите этот адрес в приложении. `npm test` проверяет локальный сервер и вспомогательную логику.
- `npm test` также проверяет отложенное применение обновлений, ошибки сети и откат версии. После `npm run build:firebase` браузерные сценарии запускаются командой `node tools/verify-web-updates.mjs` с установленными Playwright и Google Chrome. Если Playwright установлен отдельно, задайте `PLAYWRIGHT_MODULE=/абсолютный/путь/к/playwright/index.mjs`. Проверка использует временную SQLite-базу в памяти, имитацию плеера YouTube и тестовую конфигурацию Firebase; облачные данные не меняет.

## Названия и темы видео

При вставке ссылки (в том числе из Android «Поделиться») облачная версия сначала запрашивает название через oEmbed на `www.youtube-nocookie.com`. Если запрос не удался, приложение пробует Cloudflare Worker, затем `www.youtube.com`. Все запросы используют только идентификатор видео. Можно повторить загрузку или ввести название вручную. Автоматический ответ не перезаписывает название, которое вы уже начали редактировать. При смене ссылки ответ от предыдущего видео игнорируется.

При добавлении видео приложение предлагает существующие темы по словам в названии — и после загрузки с YouTube, и при ручном вводе. Отмеченные темы можно исправить перед сохранением. После ручного изменения тегов новая правка названия не меняет выбор; кнопка **Применить подсказки** позволяет явно заменить его текущими рекомендациями. Основной подбор работает через Polza (Gemini 2.5 Flash Lite) и Cloudflare Worker; отдельный API-ключ ограничен общим расходом 50 ₽. Если AI не подключён, недоступен или исчерпал лимит, используются локальные подсказки по ключевым словам. В обоих случаях результат стоит проверить. Новые темы автоматически не создаются.

В **Настройки → Темы видео** родитель может добавлять свои темы, переименовывать и удалять существующие. При добавлении или редактировании видео отметьте до 9 тем: ролик будет виден в каждой из них. Кнопка **Изменить** под видео также позволяет исправить название и заметку.

Переименование обновляет подпись на всей полке. Удаление темы убирает только этот тег; другие теги и видео сохраняются. Ролики без активных тегов отображаются в «Другое» — это служебный раздел, который нельзя удалить или переименовать. Старые видео с одной темой продолжают работать без ручного переноса. Изменения доступны детским устройствам, но управление остаётся только у родителя.

Облачная версия хранит темы в `families/{family}/categories`, а видео — с массивом `categories` и совместимым полем `category`. Удалённые темы помечаются неактивными; идентификатор не переиспользуется. Для публикации этой версии необходимы новые правила Firestore и Hosting вместе: `firebase deploy --only firestore:rules,hosting`. Проверенные локальные сборки сами по себе не обновляют опубликованный сайт.

Браузерная проверка новых тем и названий: `PLAYWRIGHT_MODULE=/путь/к/playwright/index.mjs node tools/verify-catalog.mjs`. Для облачной сборки сначала выполните `npm run build:firebase -- --emulator`, затем запустите тот же сценарий с `--emulator` внутри `firebase emulators:exec --project demo-papina-polka --only auth,firestore`. Сценарии используют отдельные временные данные, включая имитацию ответов YouTube; опубликованную полку они не меняют.

## Автообновление APK через GitHub Releases

Android начиная с 0.6.5 читает [манифест последнего релиза](https://github.com/AlxVoropaev/papapp/releases/latest/download/latest.json) и скачивает APK того же тега. Для скачивания не нужен аккаунт GitHub. Для установок 0.6.0–0.6.4 манифест по старой ссылке Яндекс Диска указывает на переходный APK 0.6.5 в GitHub. После его установки следующие обновления приходят с GitHub. APK 0.6.5 можно также установить вручную поверх прежней версии.

Новая версия проверяется при открытии/возвращении в приложение (не чаще одного раза в 15 минут) и фоновым заданием Android примерно раз в 6 часов. ОС может откладывать фоновые задания ради экономии батареи. APK загружается в приватное хранилище приложения, проверяется размер, SHA-256, имя пакета, версия и совпадение сертификата подписи с установленным приложением. Размер ограничен 50 МиБ. Неправильный или незавершённый файл не устанавливается.

Установка начинается в открытом приложении, когда закрыты формы и плеер, завершены запросы и обработаны входящие ссылки. На время подготовки отдельное окно блокирует ввод. После отмены или ошибки приложение снова принимает ввод. При установке Android перезапускает процесс и сохраняет данные приложения.

Когда Android разрешает самообновление без диалога (Android 12+ при выполнении требований платформы), используется автоматическая установка. В остальных случаях появляется штатное подтверждение Android. Разрешение «Установка неизвестных приложений» нужно выдать приложению «Видео полка» один раз при первом обновлении. Отказ откладывает следующую попытку на сутки. Первую APK-версию с загрузчиком нужно установить вручную поверх существующей.

### Выпуск следующей версии

Для выпуска с шестизначными кодами сначала обновите Cloudflare Worker (`npm run deploy:worker`). После этого можно публиковать APK и веб-сборку. Worker ограничивает число попыток ввода, а Firestore проверяет срок действия и одноразовость приглашения.

1. Увеличьте `versionCode` и `versionName` в `android/version.properties`. Номер кода версии должен строго расти. Не меняйте ключ подписи: текущие установки совместимы с `.tooling/local-debug.keystore`, который нужно сохранять и не публиковать.
2. Закоммитьте все изменения для выпуска, включая номер версии, и выполните `git push`. Соберите APK после успешного push. Для сборки нужны JDK 17, Android SDK и тот же ключ подписи, что у предыдущего APK.

   ```sh
   ./tools/build-local-apk.sh --cloud https://papina-polka-bec464.web.app
   RELEASE_DIR="$(node tools/prepare-apk-release.mjs)"
   TAG="$(basename "$RELEASE_DIR")"
   gh release create "$TAG" "$RELEASE_DIR/latest.json" "$RELEASE_DIR/"*.apk \
     --draft --target "$(git rev-parse HEAD)" --title "$TAG" --notes "Обновление Android-приложения"
   ```

3. Проверьте наличие обоих файлов в черновике. Опубликуйте выпуск и проверьте общедоступные ссылки, размер и SHA-256.

   ```sh
   gh release edit "$TAG" --draft=false --latest
   node tools/verify-apk-release.mjs
   ```

   Для исправлений выпускайте следующий номер версии. Веб-сборка публикуется в Firebase отдельно.


Gradle и скрипт сборки берут номер версии из одного файла. `POLKA_VERSION_CODE` / `POLKA_VERSION_NAME` предназначены для тестовых сборок; понижение `POLKA_TEST_TARGET_SDK` разрешено только в локальном режиме для проверки системного подтверждения на эмуляторе.

Подключение и обслуживание AI-подсказок описано в [docs/ai-tags.md](docs/ai-tags.md).

## Проверка коммитов на утечки

Установите [Gitleaks](https://github.com/gitleaks/gitleaks#installing) (на macOS — `brew install gitleaks`). После клонирования один раз включите хук в этом репозитории:

```sh
git config --local core.hooksPath .githooks
```

Перед коммитом хук проверяет изменения, добавленные через `git add`. При находке Gitleaks показывает файл и строку со скрытым значением секрета. Коммит блокируется при находке или ошибке проверки, в том числе если Gitleaks отсутствует в `PATH`.
